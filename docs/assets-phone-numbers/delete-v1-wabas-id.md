`DELETE /v1/wabas/{id}`

删除 WhatsApp 账户。cascade=true 时自上而下连同子对象一起删除（计费账本与信用账户不受影响，仅在有在途信用预留时返回 409）；不带该参数则保持原行为：存在子对象时返回 409。

:::note[鉴权]

请求头携带 `Authorization: Bearer <API_KEY>`。API Key 的可访问资源由当前授权范围决定。

:::

## 请求

Base URL：`https://api.bsptest.com`

### 参数

| 名称 | 位置 | 必填 | 类型/约束 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | path | 是 | string | 平台内 WABA ID，`waba_...` |
| `cascade` | query | 否 | `true` | 只有字面量 `true` 触发级联删除；其它值（含省略）走默认行为——存在子对象时返回 `409`。计费账本与信用账户始终不受影响 |

## 响应

| 状态码 | 说明 |
| --- | --- |
| `204` | No Content |
| `4xx` | 客户端错误 |

通用错误信封及处理建议见[错误码](../guides/error-codes.md)。

## 补充说明

不带 cascade 参数时，只要这个 WABA 下还挂着号码、模板，或者存在关联的 Embedded Signup 记录这三类子对象中的任意一种，就会返回 409（响应体里会标注具体是哪一类依赖挡住了删除，不用去猜）；cascade=true 时则会连同这些子对象一起自上而下全部删除，但计费账本流水和信用账户状态不受影响，始终保留。两种模式都受同一条"存在在途信用预留就一律不许删"的闸门约束，不管带不带 cascade 都绕不过去。
